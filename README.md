# lex_parse_by_ocaml

## What's this?
- lex_parse

言語の字句解析規則、文脈自由文法の導出規則を含む言語モジュールから、字句解析、構文解析関数を持つモジュールを作成するファンクタを含む 

- LangBuilder

構文規則を記述したファイルから lex_parse で使用する言語モジュールのスクリプトを作成する

## 開発期間・所要時間
- lex_parse 2025年4月 所要時間50時間程度(うち学習時間 20時間、実装30時間程度)
- LangBuilder 2026年 9月 所要時間10時間程度

## 動作環境・実行方法
ocaml コンパイラが必要です。
手動でもコンパイルできますが、dune パッケージを用いて依存関係を解決させた方が楽です。

実行環境
- opam 2.1.5
- dune 3.22.0
- ocaml 4.14.1

実行手順
1. ターミナルでLangBuilder/ ディレクトリに移動します
2. `dune exec LangBuilder ./bin/sampleLang.lang` を実行すると, LangBuilder ディレクトリ直下に Lang.ml が生成されます
3. Lang.ml を lex_parse/bin/ にコピーします
4. lex_parse/ ディテクトリに移動します
5. `dune exec lex_parse` を実行すると, lex_parse/bin/main.ml 内の構文解析のテストケースが実行されます。

操作方法
LangBuilder は、指定したファイルを読み込み、Lang.mlを生成します。詳細は、LangBuider/bin/sampleLang.lang を凡例として参考にしてください。
特に、token や mark のラベルは OCaml のバリアントとして扱うために大文字で始まる必要があります。また、引数を持つtokenに場合はデフォルト値も与える必要があります。細かいところは、生成されるLang.mlと比較しながら変更するのが良いと思います。

lex_parse/main.ml 内では、直接main.ml内に書かれた言語モジュールによるテストと、Lang.mlを読みこんだテストが実行されています。
Lang.mlによるテストは一番最後に書かれています。1041行目の文字列を構文解析したいプログラムに置き換えることで、構文解析と評価を行うことができます。


## 展望
いずれ ocamllex, ocamlyacc に相当する機能まで拡張したいが、ocamlがそもそもunicodeへの対応が完璧じゃないなどの理由で、別の言語への移行を検討中。

ロジックが不完全で前計算時に、言語の構文規則の順番などに応じて計算結果が変わったりする。
理論をそのまま模倣しているため、効率化、最適化など出来ていない。
構文規則から言語モジュールを作成、言語モジュールをファンクタに与えて構文解析モジュールを作成するのではなく、直接構文解析スクリプトを生成したい。
スクリプトを生成するなら metaOCaml を利用したほうが良い。

現在プログラム全体を一気に字句解析した後に構文解析を開始しているので、長大なプログラムの解析には不向き。
非同期的な手続きをモナドを利用するため Haskell を使用するか、imperativeな C や Rust に移植することを考えている。
